# Изменения защиты сервисного ядра

23 ноября 2026. Изменения поверх `c05c271`, без переделки демо-интерфейса.

## Вход интеграций

`POST /api/v1/ingest` требует отдельного `Authorization: Bearer <FLOWOPS_INGEST_TOKEN>`; минимум 32 байта, рекомендуется случайный секрет не менее 32 случайных байт. Без настройки — 503, неверный/отсутствующий секрет — 401. Используйте отдельный секрет от операторского. HTTP-адаптер с этим credential является доверенной интеграцией и отвечает за проверку sender. Токен не подтверждает личность сотрудника сам по себе и не является персональным RBAC.

Общий validator до анализа/записи ограничивает сумму subject/message с разделителем до 16 KiB, sender — 255 байт и проверяет callback. Он применяется также к workers, вызывающим IngestMessage напрямую. Большой вход отвергается, а не сохраняется после отказа анализатора.

## Исходящие callbacks

`FLOWOPS_CALLBACK_URLS` — список точных HTTPS-адресов через запятую. Пустое значение отключает callbacks, включая назначения, ранее сохранённые в БД. Для старых заявок с запрещённым callback операторский ответ не сохраняется частично: операция отклоняется целиком.

Разрешены только HTTPS, стандартный порт 443, отсутствие userinfo/fragment. Query допускается только как часть точного зарегистрированного адреса. Не передавайте секреты в URL. Запрещены redirects, proxy из окружения, private/loopback/link-local/metadata и специальные диапазоны IPv4/IPv6. Все IP DNS-ответа проверяются при соединении, затем dial выполняется по проверенному IP, сохраняя hostname для TLS. Это устраняет повторное разрешение DNS между проверкой и dial. Внутренние callbacks в этой реализации не разрешаются; для них нужен отдельный узкий согласованный механизм.

Пример только назначения:

```dotenv
FLOWOPS_CALLBACK_URLS=https://hooks.example.com/flowops/reply
```

## Политика моделей и данных

Наличие ключа не включает передачу заявок внешней модели. По умолчанию обработка локальная.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| FLOWOPS_AI_PROVIDERS | пусто | Явно согласованные `gigachat`, `gemini`, `compatible`, через запятую |
| FLOWOPS_AI_ALLOW_FALLBACK | false | Разрешение перейти к другому согласованному провайдеру после ошибки |
| FLOWOPS_AI_ALLOW_SENSITIVE | false | Разрешение внешней обработки потенциально чувствительного текста после маскирования |

Неизвестное имя в списке провайдеров выключает внешнюю обработку целиком. При false для sensitive распознанные ПДн/счета и финансовые/персональные темы направляются в локальный анализатор. Это консервативная эвристика с пропусками и ложными срабатываниями, не доказательство анонимизации. Включение sensitive не отключает маскирование; оно явно допускает обработку остаточного текста согласованным провайдером. Любое внешнее разрешение должно учитывать возможность нераспознанных чувствительных сведений.

Идентификатор sender больше не добавляется в prompt. Email в верхнем регистре и 20-значные счета маскируются. KB по-прежнему не отправляется модели; строгий контракт ответов сохранён. Endpoint модели должен использовать HTTPS, credentials/fragment в URL запрещены. Возможность отключить проверку сертификата GigaChat удалена из транспорта; старое insecure-настройка исключает этот провайдер из согласованной цепочки. Все provider redirects запрещены.

Бюджет 60/min и 4 одновременных вызова теперь относится к внешней обработке. Локальная классификация работает при исчерпании бюджета и при пустой политике. Это не общий лимит всей очереди/БД и не замена распределённым квотам.

## Каналы

MAX требует HTTPS, проверяет сертификаты и не следует redirects. `MAX_INSECURE_TLS=true` больше не поддерживается: запрос отвергается до отправки токена. Значение по умолчанию в запуске/примерах изменено на false. Нужный доверенный CA устанавливается обычным способом, без обхода TLS.

Telegram также не следует redirects. JSON polling-ответов ограничен 1 MiB; drain тела отправки ограничен 4 KiB. SMTP-соединение ограничено общим сроком 30 секунд и закрывается по отмене context, включая greeting/auth/data. IMAP использует отмену родительского context и 30-секундные дедлайны на greeting/I/O-команды, без срока на всю обработку mailbox. Ошибка FETCH/STORE прекращает текущий poll. Протокольная строка IMAP ограничена 64 KiB, ответ — 32 MiB, MIME-вложенность — 16 уровней. Ошибки транспортов в журналах не содержат исходные URL/токены.

Отключённый dispatcher или неизвестный адресат теперь возвращает ошибку вместо ложного подтверждения доставки.

## Надёжная доставка ответов оператора

Миграция добавляет `ticket_deliveries`, `delivery_status`, `reply_version`, `reply_hash`. Сохранение ответа, события доставки и запись аудита выполняются одной транзакцией; ошибка любого шага откатывает всё. POST Reply и PATCH с operator_reply используют один путь. На канал и callback создаются отдельные события.

- Worker забирает по одному событию через `FOR UPDATE SKIP LOCKED`, lease — 60 секунд, сетевой вызов — до 20 секунд.
- После сбоя или перезапуска просроченный lease позволяет повтор. Пауза повторов растёт до 256 секунд; после 10 неуспешных попыток — failed. Повторная явная отправка того же ответа возобновляет failed-событие.
- Одинаковый повтор запроса внутри версии не создаёт дубликат. При изменении текста создаётся новая версия; A→B→A снова отправляет A. Неначатые старые события становятся superseded; ACK старого worker не закрывает новую версию.
- Для ожидающей/неудачной внешней доставки автоматический статус остаётся resolved; `delivery_status` — pending/failed. После приёма ответа всеми адресатами текущей версии — closed/sent. Для web/API без внешнего адресата — closed/not_required: ответ уже сохранён для чтения через API.
- Это **at-least-once**. Если адресат принял сообщение, а процесс умер до фиксации sent, возможен повтор. Уже начатую отправку нельзя гарантированно отозвать после редактирования ответа. Ответ 2xx/SMTP означает приём платформой, не прочтение сотрудником.

## Зависимости

Минимальная версия Go — 1.26.11; pgx/v5 — 5.9.2; x/text — 0.41.0. Неиспользуемая косвенная зависимость x/crypto удалена go mod tidy. После изменений `govulncheck v1.10.0` не обнаружил известных уязвимостей в проверенной сборке. Это результат на дату проверки, а не бессрочная гарантия.

## Проверки

Обычный запуск: `go test ./...`, `go vet ./...`. Негативные сценарии охватывают callback URL/DNS/IP/redirect, небезопасный MAX, отсутствие разрешения модели, sender в payload, fallback, финансовый текст, локальный анализ при исчерпании бюджета и авторизацию интеграций.

Интеграционные тесты запускаются с `FLOWOPS_TEST_DATABASE_URL`, указывающим **только** на отдельную БД с именем `flowops_security_test`. Каждый тест создаёт и удаляет собственную схему; миграции выполняются повторно. Проверяются запись+аудит+события, откат, повторы, перезапуск worker, параллельные claims, истёкший lease, terminal failure, supersede и версии A→B→A. Эти тесты пропускаются без явного тестового DSN, а не используют DATABASE_URL рабочего сервиса.

При реализации проверки выполнены на временном PostgreSQL 16.4 на loopback со случайным портом. Синтетический sender заменял отправку реальных сообщений. Образ production, живые платформы и боевая БД не использовались. Race detector не запускался: в среде отсутствует CGo toolchain; конкурентный claim проверен интеграционным тестом.

## Что остаётся отдельной работой

Автоматические первичные ответы workers и подтверждение чтения входящих писем ещё не переведены на durable outbox/inbox: при сбое между сохранением и подтверждением возможны повторы/потеря автоответа. Требуется дедупликация по стабильному ID платформы/UID почты. Отдельно остаются привязка внешнего отправителя к сотруднику, права на аудиторию KB, персональные роли операторов, общий/распределённый admission limit, retention событий и проверка реального развёртывания. Демо-эндпоинты не превращены в защищённый корпоративный портал и не должны публиковаться как production API.

Первоначальные отчёты описывают состояние `c05c271`; их доказательства PASS=воспроизведение дефекта являются историческими. Для исправленного состояния используйте новые обычные/integration-тесты, а не старый overlay с ожиданием уязвимого поведения.
