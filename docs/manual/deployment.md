# Запуск и сопровождение

## Docker

Требуются Docker и Compose. В корне проекта скопируйте `.env.example` в `.env`, заполните настройки и выполните:

```bash
docker compose up -d --build
docker compose ps
```

Сайт по умолчанию: `http://localhost:8080`. PostgreSQL в текущем Compose опубликован на `127.0.0.1:5433`; внутри сети контейнеров используется `db:5432`. Данные БД хранятся в именованном томе. Остановка контейнеров без удаления тома не равна очистке БД.

## Запуск без Docker

Нужны Go 1.26.11 или новее и совместимый PostgreSQL. Заполните `.env` в корне проекта: сервер загружает его при старте. Переменные, уже заданные окружением, имеют приоритет.

```bash
go mod download
go run ./cmd/server
```

Команда запускается из корня репозитория: оттуда читаются `web`, `knowledge_base` и `LICENSE`. Миграции применяются при старте. Перед обновлением рабочей базы делайте резервную копию.

## Основные переменные

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Подключение PostgreSQL вне встроенной настройки Compose |
| `PORT` | Порт HTTP, обычно 8080 |
| `FLOWOPS_OPERATOR_TOKEN` | Bootstrap-доступ для совместимости; не выдавать сотрудникам |
| `FLOWOPS_INGEST_TOKEN` | Отдельный доверенный токен внешнего ввода |
| `FLOWOPS_COOKIE_SECURE` | Secure-cookie при HTTPS |
| `FLOWOPS_PUBLIC_URL` | Публичный адрес для ссылок QR |
| `FLOWOPS_AI_PROVIDERS` | `yandex` для разрешённого внешнего провайдера; пусто — локально |
| `YANDEX_API_KEY` / `YANDEX_FOLDER_ID` | Реквизиты AI Studio |
| `YANDEX_MODEL` | Поддерживаемая модель, текущий пример — `aliceai-llm` |
| `FLOWOPS_AI_ALLOW_SENSITIVE` | Отдельное глобальное разрешение чувствительных данных |
| `FLOWOPS_CALLBACK_URLS` | Точные HTTPS-адреса внешних workflow callbacks |
| `FLOWOPS_1C_ALLOWED_URLS` | Точные базовые адреса 1С |
| `FLOWOPS_1C_SECRET_KEY` | 32 случайных байта Base64 для шифрования реквизитов 1С |

Настройки организации дополнительно ограничивают возможности ИИ. Значения ключей не коммитятся. Старые названия провайдеров в исторических конфигурациях не означают поддержку альтернативного production-провайдера.

## Обновление

После получения изменений выполните `docker compose up -d --build app`, проверьте состояние контейнера и сообщение запуска в журнале. Если миграция не проходит, не удаляйте БД ради запуска: изучите ошибку и восстановите согласованную версию/копию.

## Резервное копирование

Сохраняйте PostgreSQL, конфигурацию среды и ключ шифрования 1С отдельно от открытого репозитория. При использовании файловых tenant-регламентов учитывайте каталог знаний и способ его размещения. Проверяйте восстановление на отдельном окружении. Без ключа 1С восстановленная БД не позволит расшифровать пароль.

Сроки хранения сообщений, файлов, артефактов и аудита определяет владелец установки. Автоматическая универсальная политика удаления не заявлена. Персональная очистка очереди не удаляет эти данные.

## Проверки разработки

```bash
go test ./... -count=1 -timeout=240s
go vet ./...
node --test tests/*.test.cjs
```

БД-тесты включаются через `FLOWOPS_TEST_DATABASE_URL` и должны использовать только отдельную тестовую базу `flowops_security_test`; временные схемы создаются и очищаются тестами. Не направляйте тестовый URL на рабочую базу.


## Дополнительный сертификат для API Яндекса

Если Windows успешно обращается к Яндексу, а контейнер пишет `x509: certificate signed by unknown authority`, проверьте издателя сертификата из контейнера. Антивирус или корпоративный прокси может проверять HTTPS и подписывать соединение собственным сертификатом, которому Windows уже доверяет, а контейнер — ещё нет.

`YANDEX_CA_FILE` задаёт путь к PEM-файлу доверенного центра сертификации внутри процесса приложения. Дополнительное доверие действует только для HTTPS-запросов к `ai.api.cloud.yandex.net`; системные корни и проверка имени сервера сохраняются. Некорректный или недоступный файл приводит к отказу соединения. Не используйте отключение проверки TLS.

Экспортируйте только публичный сертификат центра из доверенного хранилища своего компьютера после проверки его происхождения. Закрытый ключ не нужен. Сохраните файл локально, например `.local/yandex-ca.pem`, и подключите через локальный `docker-compose.override.yml`:

```yaml
services:
  app:
    environment:
      YANDEX_CA_FILE: /app/local-certs/yandex-ca.pem
    volumes:
      - ./.local/yandex-ca.pem:/app/local-certs/yandex-ca.pem:ro
```

Примените `docker compose up -d --build app`. Каталог `.local` и локальный override исключены из Git и Docker build context: сертификат конкретного компьютера не встраивается в образ и не публикуется. При смене сертификата обновите PEM-файл и перезапустите приложение. Если проверка HTTPS не используется и стандартная цепочка доверия работает, дополнительный сертификат не требуется.
