# Структура организации

Страница: `/settings/structure`. Изменение доступно администратору с `units_manage`.

## Подразделения и иерархия

Нажмите «Добавить подразделение». Укажите название, тип, родительский узел и стабильный код маршрутизации. Тип описывает назначение узла; филиалы и вложенные отделы строятся тем же деревом.

Родителя выбирают из своей организации. Нельзя сделать подразделение собственным предком: сервер проверяет циклы. Стабильный код связывает подразделение с очередью и правилами маршрутизации; это не отображаемое имя, которое можно менять бездумно.

## Участники

Добавьте нужных участников в подразделение и укажите предусмотренную связь: обычное участие, руководитель, заместитель или ответственный. Один сотрудник может состоять в нескольких подразделениях. Членство в структуре не заменяет базовую роль и набор разрешений.

При ограничении доступа по подразделению сервер учитывает разрешённое поддерево и актуальное членство. Список служебных ID участников не публикуется любому сотруднику через общий каталог.

## Изменение и отключение

Откройте узел, исправьте поля и сохраните. «Отмена» закрывает редактирование без сохранения. При конкурирующей правке применяется контроль ревизии.

Отключение узла рекурсивно отключает потомков и убирает соответствующие управляемые маршруты из активных очередей. Исторические тикеты и события остаются в БД. Перед отключением проверьте резервный отдел и действующие правила.

API: `GET/POST /api/v1/organization/units`, `PUT /api/v1/organization/units/{id}`. Безопасный каталог для селекторов — `/api/v1/organization/directory`; состав ответа зависит от прав.
