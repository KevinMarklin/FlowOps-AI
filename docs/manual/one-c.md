# Подключение 1С

Страница: `/settings/1c`. Администратор должен иметь `integrations_manage` и доступ ко всей организации.

## Подготовка

На стороне 1С опубликуйте стандартный OData или собственный HTTP-сервис. Создайте отдельного пользователя с нужными правами. В конфигурации FlowOps добавьте точный базовый адрес в `FLOWOPS_1C_ALLOWED_URLS` и ключ шифрования в `FLOWOPS_1C_SECRET_KEY`. Адреса разделяются запятыми; пустой список отключает доступ к внешним базам.

Для 1С на Windows адрес должен быть доступен из контейнера. `localhost` внутри Docker указывает на контейнер; для хоста обычно используют `host.docker.internal`. Доверенные внутренние адреса разрешаются явно. Для внешней сети используйте HTTPS с действительным сертификатом.

## Настройка формы

Выберите OData или HTTP JSON. Укажите базовый адрес, тип авторизации, логин для Basic и пароль/токен. Для собственного HTTP-сервиса укажите относительный путь проверки, например `health`. Для OData проверяется `$metadata`.

Сохраните настройки и нажмите «Проверить соединение». При OData успешный ответ предлагает опубликованные ресурсы. При HTTP проверка ожидает JSON. Изменённые несохранённые поля не используются для запроса к старому соединению: сначала требуется сохранение.

Секрет шифруется AES-256-GCM с привязкой к компании. API не возвращает его в браузер. Пустое поле сохраняет прежний секрет только для того же адреса, логина и способа авторизации. При их смене нужен новый секрет. Для удаления выберите авторизацию без реквизитов и отметьте удаление.

## Чтение данных

Укажите ресурс, например `Catalog_Сотрудники`, число пропущенных записей и размер страницы от 1 до 100. Нажмите «Загрузить данные». Ответ JSON показан в прокручиваемом поле. Следующая страница загружается явно с новым смещением.

OData получает `$format=json`, `$top` и `$skip`. Собственный HTTP-сервис получает `limit` и `offset` и должен сам поддерживать эти параметры. Ограничения: до 2 МиБ ответа и 10 секунд на запрос. Сервер не переходит автоматически по `nextLink`, не следует редиректам, не использует системный прокси и не отключает проверку TLS.

## Границы реализации

Коннектор выполняет GET-запросы и не содержит общего прокси с произвольным URL. Автоматической синхронизации сотрудников, записи документов, обмена статусами и бухгалтерских проводок нет. Схема этих операций зависит от конфигурации 1С и требует отдельного соглашения о полях и правах. Реальная база пока не предоставлена; проверки выполнены на изолированных стендах.

Для входящих тикетов 1С может использовать существующий ingest API с отдельным ключом. Это другой поток обмена, не выдающий 1С административный доступ.

API: `GET/PUT /api/v1/integrations/1c`, `POST /api/v1/integrations/1c/check`, `GET /api/v1/integrations/1c/data?resource=...&skip=0&limit=20`.

Источники протокола: [REST interface 1C](https://1c-dn.com/1c_enterprise/rest_interface/?type=original), [публикация и интеграция](https://1c-dn.com/blog/methods-of-integration-with-1c-enterprise-applications/).
