# Объекты и QR-коды

Страница: `/settings/assets`. Управление доступно администратору с разрешением на подразделения.

## Карточка объекта

Создайте объект, укажите название, тип, подразделение и контекст для обращения. Типы: помещение, рабочее место, принтер, проектор, компьютер и другое оборудование. Активность определяет возможность использовать объект при новой подаче заявки.

Контекст должен помогать специалисту: расположение, инвентарный ориентир, модель или особенности доступа. Не размещайте пароли и секреты в описании. Сохранение проверяет компанию, подразделение и ревизию.

## QR-код

После сохранения активного объекта получите PNG QR. В коде находится ссылка с непрозрачным ID объекта, а не пароль, токен или полный текст описания. Базовый публичный адрес задаёт `FLOWOPS_PUBLIC_URL`.

Для сотрудников с других устройств используйте адрес, который им доступен. QR с `localhost` открывает локальный компьютер сканирующего устройства и годится только для разработки на том же устройстве.

## Сканирование

Пользователь переходит по ссылке, входит и видит форму с объектом. Сервер проверяет организацию и область доступа, затем подставляет контекст. При отправке тикет получает снимок контекста; последующая правка объекта не должна менять смысл уже поданной заявки.

Если объект отключён или недоступен, приложение предлагает продолжить без него, а не подставляет случайное оборудование. Удаление контекста перед отправкой создаёт обычное обращение.

API: `/api/v1/assets`, `PUT /api/v1/assets/{id}`, `GET /api/v1/assets/{id}/qr`, `GET /api/v1/assets/{id}/context`.
