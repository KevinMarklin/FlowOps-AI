# Организация и SLA

Страница: `/settings/organization`. Администратор управляет настройками; отдельные операции дополнительно требуют соответствующих разрешений.

## Профиль организации

Название, описание, сфера деятельности и контактная почта описывают рабочее пространство. Часовой пояс задаётся именем IANA, например `Europe/Moscow`. Он нужен для рабочих календарей и интерпретации времени. Изменение профиля не переименовывает автоматически внешнюю базу 1С или аккаунты ботов.

## Рабочий календарь

Выберите рабочие дни, начало и конец дня, перечислите нерабочие даты. Число дня недели в программных политиках: 0 — воскресенье. Исключённые даты не считаются рабочими, даже если совпали с обычным рабочим днём.

Для SLA можно считать календарное время либо время по рабочему календарю. Настройте первый ответ и решение в минутах. Не путайте эти сроки с таймером активной работы оператора: SLA описывает обязательство по сроку обслуживания.

## Экономические параметры

Валюта задаётся кодом ISO. Стоимость часа и отдельные ставки подразделений используются для оценок стоимости рабочего времени. Базовая длительность ручной обработки служит допущением для сценарных сравнений. Укажите инфраструктуру, внедрение и сопровождение, если эти суммы подтверждены.

Незаполненные расходы не равны доказанному отсутствию затрат. При недостаточной финансовой базе приложение не должно выдавать неподтверждённую окупаемость.

## Причины закрытия

Добавьте стабильный код причины и понятное название. Этот справочник используется при закрытии тикета и в аналитике. Перед удалением или переименованием учитывайте уже существующие записи. В тикете показывается сохранённая причина закрытия.

## Сохранение

Нажмите «Сохранить настройки». Конфигурация имеет ревизию: конфликт изменений требует обновить данные и повторно применить правку. Сервер сравнивает изменяемые разделы и проверяет необходимые разрешения, а не полагается на видимость полей в браузере.

Расширенные политики SLA по условиям, эскалации и паузы описаны в [правах и процессах](/documentation/governance).

API: `GET/PUT /api/v1/settings/organization`; публичные для участника сведения организации — `GET /api/v1/organization`.
