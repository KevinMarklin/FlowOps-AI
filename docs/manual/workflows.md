# Бизнес-процессы

Страница: `/settings/workflows`. Определения настраивает администратор с правами автоматизации. Запуск из тикета требует разрешений на соответствующие действия.

## Редактор

Создайте новый процесс: код, название, общий срок в минутах и доступность для запуска. Добавляйте шаги со стабильными ID и предшественниками. Одинаковый предшественник у двух шагов создаёт параллельные ветви. Завершающий шаг должен ждать необходимые ветви.

Поддерживается направленный ациклический граф из 2–60 узлов с одним началом и завершением. Сервер проверяет ссылки, циклы, достижимость и схождение ветвей. Общий срок — от 1 до 10080 минут. Сохранение не запускает процесс на существующих тикетах.

## Типы шагов

| Тип | Что выполняется |
|---|---|
| Начало | Отмечает запуск экземпляра |
| Условие | Проверяет настроенные значения и определяет активность ветви |
| Сбор / проверка данных | Ждёт или проверяет обязательные поля обращения |
| Назначение | Назначает предусмотренного исполнителя |
| Задача | Создаёт связанное поручение ответственному |
| Передача | Меняет отдел в допустимом контексте |
| Согласование | Ждёт решения назначенного участника |
| Уведомление | Создаёт внутреннее уведомление для получателя |
| Ожидание события | Ждёт сохранённое событие, например новое сообщение сотрудника |
| HTTP | Отправляет разрешённому внешнему API POST с метаданными шага |
| Завершение | Завершает экземпляр после требуемых зависимостей |

Поля условий относятся к текущему тикету и настроенным полям формы. Исполнитель и отдел должны существовать в компании. Условие фиксируется при начале шага: изменение тикета не отменяет уже выданное согласование. Для ещё не начатых шагов используются актуальные данные.

## Пропуск ветвей и параллельность

Ложное условие пропускает соответствующую ветвь. Если все родители пропущены, пропуск распространяется дальше. Узел с завершённой активной ветвью может продолжиться после разрешения зависимостей. Завершение проверяет схождение ветвей; это не свободное продолжение по любому одному стрелочному переходу.

## Запуск и исполнение

На странице тикета выберите активный процесс и подтвердите запуск. Сервер сохраняет неизменяемый снимок определения. Фоновый обработчик периодически выбирает незавершённые экземпляры, блокирует записи на время шага и сохраняет действия вместе с контрольной точкой.

Перезапуск приложения не удаляет состояние. Повтор запроса запуска с тем же ключом возвращает тот же запуск. Перед исполнением проверяются актуальные права инициатора; отмена, срок или терминальная ошибка прекращают последующие эффекты и открытые задачи.

## Внешний HTTP-шаг

Адрес должен точно входить в `FLOWOPS_CALLBACK_URLS`; допускаются разрешённые HTTPS-адреса с контролем DNS, без произвольных редиректов и обхода через прокси. Получатель должен поддерживать идемпотентность по ключу экземпляр/шаг. Количество повторов ограничено: 0–5.

Локальные изменения фиксируются до внешней отправки. После сетевого обрыва запрос может прийти получателю повторно, поэтому распределённое «ровно один раз» без поддержки внешней системы не обещается. Шаг передаёт предусмотренные метаданные, а не произвольную выгрузку переписки.

## Отмена и Copilot

Отмена сохраняется в БД и предотвращает последующие шаги. Уже выполненный внешний эффект автоматически не откатывается. Copilot может предложить существующий активный процесс, но запуск остаётся отдельным действием человека.

API: определения — `/api/v1/workflows`; запуск/история — `/api/tickets/{id}/workflows`; задачи — `/api/v1/workflow-tasks`; отмена — `/api/v1/workflow-runs/{id}/cancel`.
