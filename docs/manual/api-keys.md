# API-ключи

Страница: `/settings/api`. Ключи нужны для внешнего ввода обращений и сайта; они не заменяют персональный доступ администратора.

## Выпуск ingest-ключа

Введите понятное название интеграции, например «1С — обращения», и нажмите «Выпустить ingest-ключ». Скопируйте показанный секрет в защищённую конфигурацию интеграции. После закрытия результата полный ключ повторно не выдаётся; каталог содержит метаданные и префикс.

Ключ связан с компанией и областью `ingest`. Внешний сервис не выбирает произвольную компанию полем JSON. Для виджета используется отдельная область `widget` и разрешённый origin.

## Управление

Список показывает название, тип, активность и доступные даты использования. Кнопка обновления повторно загружает состояние. Неиспользуемый или скомпрометированный ключ отзовите и выпустите новый. Отзыв не удаляет ранее созданные обращения.

Нельзя применять ingest-ключ к API команды, ролей, скачиванию чужих вложений или настройке Яндекса. Браузерный сеанс сайта, интеграционный ключ и токен бота имеют разные назначения.

## Пример внешнего вызова

```bash
curl http://localhost:8080/api/v1/ingest \
  -H 'Authorization: Bearer YOUR_INGEST_KEY' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: external-case-2026-001' \
  -d '{"channel":"API","sender":"external-user-17","message":"Не работает рабочий сервис"}'
```

Используйте актуальные поля контракта ingest; повтор одной операции должен сохранять тот же ключ, новая операция — получать новый. Подробная схема и назначение полей описаны в [справочнике API](/documentation/api).

API: `GET/POST /api/v1/keys`, `DELETE /api/v1/keys/{id}`.
