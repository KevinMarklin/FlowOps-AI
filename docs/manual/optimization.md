# Центр оптимизации

Страница: `/optimization`. Аналитик и администратор просматривают результаты; решения по внедрению изменяет администратор.

## Провести анализ

Выберите даты, подразделение и состояние рекомендации. Обычный анализ применяет детерминированные признаки к реальным обращениям: нормализованные повторы, решённые вручную случаи без инструкции, нарушения настроенного SLA, многократные перенаправления и старый незакрытый остаток.

Каждая рекомендация содержит основание, объём обращений, доступное измеренное время и сценарную оценку потенциала. У пользователя без доступа к деталям не должны появляться скрытые ID чужих тикетов только ради объяснения агрегата.

## Семантический анализ ИИ

Запускается отдельной кнопкой и обращается к настроенному Яндексу. В модель передаётся ограниченная маскированная выборка, максимум 30 обращений. Возвращённые ссылки на источники проверяются по исходной выборке компании.

Если модель недоступна, анализ завершается ошибкой без создания фиктивных групп. Число обращений и экономические расчёты остаются серверными величинами, а не произвольными оценками модели.

## Работа с рекомендацией

Изучите основание и ограничения. Администратор может принять рекомендацию, отклонить, отложить или отметить внедрённой; записать примечание и добавить задачи внедрения с ответственными. Изменение сохраняется с контролем версии, чтобы случайно не затереть чужое решение.

Из подходящих закрытых обращений можно подготовить черновик регламента. Генерация не публикует его автоматически: дальнейшая работа продолжается в базе знаний.

## Как трактовать эффект

Сохранённое основание решения относится к конкретной выборке и отличается от текущих фильтров. «Внедрено» — состояние управленческого решения, а не автоматически подтверждённая экономия. Для оценки результата сравните последующие данные и учитывайте неполноту наблюдений.

API: `GET /api/optimization`, `PUT /api/optimization/{id}`, `POST /api/optimization/semantic`.
