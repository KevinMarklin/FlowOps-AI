# Архитектура и данные

## Компоненты

Бэкенд написан на Go и использует `net/http`, маршруты ServeMux и pgx для PostgreSQL. Интерфейс — HTML, CSS и обычный JavaScript без отдельного frontend-сервера. `cmd/server` собирает зависимости, регистрирует API и запускает обработчики каналов и фоновые задачи.

| Каталог | Назначение |
|---|---|
| `internal/handlers` | HTTP-операции, валидация, транзакционные прикладные сценарии |
| `internal/security` | Сеансы, роли, разрешения, CSRF, ключи и сетевые ограничения |
| `internal/database` | Подключение и последовательные миграции |
| `internal/analyzer` | Анализ обращения, политика и вызовы Яндекса |
| `internal/knowledge` | Поиск допустимых регламентов и снимки каталога |
| `internal/channels` | Telegram/MAX/email и нормализация сообщений |
| `internal/workflows` | Определение и долговечное исполнение процессов |
| `internal/onec` | Проверяемый GET-клиент 1С и шифрование секрета |
| `web` | Интерфейс, виджет, маршрутизация разделов |
| `docs` | Руководство и встроенный публичный просмотр документации |

## Изоляция

Рабочее пространство задаётся авторизованным principal. SQL-фильтры используют `tenant_id`, ID пользователя и при необходимости область роли. Нельзя выбрать чужую компанию произвольным параметром JSON. Доступ к вложениям, событиям, знаниям и артефактам проверяется отдельно.

Базовые роли ограничиваются пользовательскими разрешениями и областью own/organization/units/resources. Для модулей, не умеющих безопасно ограничить общий контекст тем же срезом, ограниченный доступ запрещается целиком.

## Долговечность

Тикеты, сообщения, ответы, причины закрытия, снимки форм, события, учёт работы, задачи, отчёты и настройки сохраняются в БД. Знания имеют версии и отдельную опубликованную ревизию. Для совместимости сохраняется файловая база стартовых материалов.

Создание тикета и запись ключа повтора выполняются одной транзакцией. Внешняя доставка и HTTP-эффекты не могут считаться одной распределённой транзакцией с произвольным внешним сервисом: применяются контрольные точки, повторные попытки и идемпотентность получателя.

## ИИ

Поддерживаемый production-провайдер — Яндекс AI Studio. Локальные правила и поиск работают отдельно от генерации. Перед внешним вызовом проверяются режим, чувствительность, источники и дневной лимит; применяются маскирование и ограничение контекста.

Структурированные ответы проверяются на известные источники, допустимые отделы и IDs. Отказ провайдера не заменяется выдуманным результатом. Copilot и семантические проверки не получают произвольных административных инструментов.

## Фоновые задачи

Сервер выполняет доставку каналов, SLA-проверки, workflow и расписания отчётов. Состояние долговечных задач сохраняется, однако обработка требует запущенного приложения. Блокировки строк и транзакции предотвращают конкурирующее независимое выполнение одного локального шага.

## Страницы и документация

Клиентская карта разделов находится в `web/routes.js`, серверные маршруты — в `cmd/server/routes.go`. Для прямых ссылок отдаётся HTML оболочка, после входа восстанавливается раздел. Документация встроена в Go-бинарник из `docs/manual/*.md`; маршруты `/documentation` и `/license` публичны и не обращаются к данным компании.

Неизвестный slug документации возвращает 404. Произвольный путь к файлу не принимается. Markdown преобразуется с отключённым исходным HTML и небезопасными ссылками. Текст лицензии выдаётся отдельным фиксированным маршрутом.
