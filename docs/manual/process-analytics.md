# Аналитика процессов

Страница: `/analytics/processes`. Права аналогичны общей аналитике.

## Расчёт

Задайте начало и окончание периода. При необходимости укажите дату внедрения изменения и нажмите «Рассчитать маршруты». Сервер агрегирует фактически сохранённые события: состояния, переходы между отделами, назначения, ожидания и этапы бизнес-процессов.

Результат помогает найти длинные ожидания, часто встречающиеся маршруты, возвраты и циклы. Например, IT → HR → IT является наблюдаемым возвратом; его наличие не объясняет автоматически причину задержки.

## Время и полнота данных

Календарная длительность этапа и активное рабочее время различаются. Первый показатель описывает интервал между событиями, второй — записанную работу специалиста. В параллельном процессе интервалы перекрываются; их нельзя просто сложить и назвать длительностью всего процесса.

Для старых тикетов подробные события могли ещё не записываться. Покрытие истории показывается отдельно. Сервис не восстанавливает несуществующие переходы только по текущему статусу.

Среднее и медиана описывают доступные наблюдения. Для интерпретации проверяйте размер выборки, канал и сложность обращений: один длинный кейс может сильно менять среднее.

## До и после

Дата внедрения разделяет наблюдения на две группы. Это сравнение показывает ассоциацию во времени, а не доказанный причинный эффект. Если одновременно изменились нагрузка, состав команды или регламенты, их влияние не изолируется автоматически.

API: `GET /api/analytics/processes`; общие фильтры аналитики и дополнительный `change_at`. События конкретного тикета доступны через `/api/tickets/{id}/events` при праве на тикет.
