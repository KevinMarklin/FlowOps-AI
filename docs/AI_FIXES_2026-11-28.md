# Исправление работы ИИ — 28 ноября 2026

## Подтверждённая причина сбоя в запущенном приложении

Предыдущий живой тест выполнялся с Windows. В Docker реальное обращение к Яндексу падало с `x509: certificate signed by unknown authority` и переключалось на локальные эвристики. TLS-соединение из контейнера предъявляло сертификат API, выданный установленным на компьютере Kaspersky. Windows доверяла этому центру, контейнер — нет. Поэтому успешный тест с Windows не доказывал доступность модели в самом приложении.

Добавлена настройка `YANDEX_CA_FILE`: PEM доверенного центра дополняет стандартные корни **только для запросов к API Яндекса**. Проверка имени сервера и TLS сохранена. Неисправный файл приводит к отказу. На этом компьютере публичный сертификат экспортирован из уже доверенного хранилища Windows, сохранён в `.local/yandex-ca.pem` и подключён read-only через локальный `docker-compose.override.yml`. Эти файлы не публикуются и не попадают в образ. Порядок настройки описан в [развёртывании](manual/deployment.md).

После исправления из контейнера отдельно подтверждены классификация и структурированная генерация через Yandex. Затем выполнена проверка кнопкой сайта «Проверить ответ» без создания тикета и отправки сообщений: основной процесс приложения получил HTTP 200 от Яндекса. Для вопроса о VPN в текущей базе организации подходящего регламента не оказалось; сервис корректно показал передачу специалисту, а не выдумал инструкцию.

## Исправления поведения

- **Уточнения.** Добавлены VPN, принтер, ноутбук и неопределённое обращение о помощи; распознаются «авторизоваться», 1С и корпоративная почта. Явно названные сервис, ошибка, местоположение и выполненные проверки повторно не запрашиваются. Сохранены пропуск, лимиты и отсутствие опроса для обычных FAQ.
- **Применимость источника.** Вопрос об определении VPN/SSO больше не получает инструкцию настройки только из-за совпадения названия. Для определения требуется объясняющее предложение об этой же теме. Если такого источника нет, автоматическое решение не выдаётся.
- **Неуспешные попытки.** При явном сообщении «перезапуск не помог» полный регламент не повторяется как новое решение. Обращение остаётся для специалиста.
- **Контекст Copilot.** Последняя явно названная текущая задача используется для поиска источников и маршрутизации; решённая VPN-проблема не перебивает новый вопрос об отпуске. Короткие продолжения «Не помогло», «Нет», «Ошибка 809» сохраняют исходную тему.
- **Лишние вопросы Copilot.** Если обязательные данные известны, проверки не помогли и опубликованный регламент задаёт следующий шаг — специалиста, дополнительный опрос прекращается. При неполных данных вопросы остаются.
- **Черновики.** Для каждого действия задан отдельный контракт. Исправлены маркеры нумерации вопросов. Неподтверждённые обещания действий заменяются явным запросом проверки с `requires_review` и предупреждением, видимым специалисту. Для такого результата кнопка вставки черновика скрывается. Проверки допустимых источников, отделов, процессов и вредоносных инструкций сохранены.

В общей матрице уточнено одно ожидание: «Принтер не печатает» уже содержит симптом, поэтому нужны место и выполненные проверки, а не повторный вопрос о симптоме. Это изменение соответствует требованию не спрашивать известное. Для безуспешных попыток ожидается передача специалисту, а не повторная выдача того же регламента. ## Практические границы

Уточняющий опрос и часть проверок применимости по-прежнему основаны на ограниченных локальных правилах. Они покрывают воспроизведённые сценарии, но не гарантируют понимание любой формулировки. Copilot остаётся черновиком с подтверждением специалиста. Проверка обещаний не является универсальной проверкой истинности всех утверждений модели. Три успешных прогона — проверка устойчивости этой выборки, а не доказательство 100% точности на любых вопросах.

Неподходящий или отсутствующий опубликованный регламент означает передачу специалисту. Автоматический ответ не должен заполнять отсутствие достоверного источника выдуманными правилами. При изменении антивирусного сертификата нужно обновить локальный PEM и перезапустить контейнер.
