# Как доказать пользу FlowOps на пилоте

Главная позиция: управляемая первая линия внутренних обращений. Наличие ИИ,
TTL или канала само по себе не доказывает превосходство над другой системой.

## Рабочее время оператора

В очереди нажмите «Работать с обращением»: поле ответа откроется сразу.
Фокус в поле ответа также запускает учёт. Новая заявка или заявка с ожидающим подтверждения регламентом при этом передаётся оператору. «Пауза», уход из окна, смена вкладки
или минута без ввода останавливают его. Возобновление ввода продолжает учёт.
Один оператор не может одновременно учитывать два обращения.

Сервер получает подтверждения раз в15 секунд и принимает максимум30 секунд
между ними. Клиент не может прислать произвольную длительность. При закрытии
обращения или сохранении ответа сессии останавливаются в той же транзакции.

Это наблюдаемая активность интерфейса, не точный хронометраж мышления человека.
Последний интервал при обрыве может быть недоучтён или отличаться до30 секунд.
Показатель не предназначен для оценки конкретных сотрудников.

Аналитика показывает общее время, число измеренных обращений и среднее время.
Расчётная экономия по Deflection Rate остаётся отдельной оценкой. Заявки с зарегистрированной работой оператора не считаются полностью самостоятельным решением. Вычитать
активное время из условной базы без контрольной группы нельзя.

## Исправления маршрутизации

Изменение отдела оператором записывается атомарно с самим изменением.
Повторное сохранение того же отдела не увеличивает счётчик. В аналитике доступны
число затронутых обращений и число изменений. Смена отдела может быть связана
с уточнением проблемы, а не ошибкой модели: это не процент точности ИИ.

## Проверка качества

```powershell
go run ./cmd/evaluate -out reports/pilot-quality.json
```

Команда по умолчанию отключает внешние провайдеры и использует12 размеченных
синтетических обращений и отдельную тестовую базу знаний. Проверяются отдел,
приоритет и конкретный источник либо отсутствие регламента. В отчёт не попадают
полные тексты запросов/ответов. Рабочая БД сервиса не используется.

`-allow-external` разрешает явно настроенный провайдер для синтетического набора;
перед таким запуском нужно передать переменные среды разрешённого провайдера.
В отчёте сохраняется фактический источник анализа каждого случая, включая fallback.
Значение100% на12 учебных примерах не является точностью на реальных данных.

Для настоящего пилота владелец процесса должен независимо разметить более широкий
набор: разные формулировки, сложные и неоднозначные обращения, отсутствие инструкции,
устаревшие регламенты, смешанные темы и атаки. Не подбирайте тесты только под код.

## Сравнение до/после

1. Согласуйте категории, правила срочности и действующие регламенты.
2. Разделите сопоставимые обращения на ручную контрольную и автоматизированную группы.
3. Измеряйте активное время, ожидание, подтверждённые решения, переадресации и качество.
4. Раздельно покажите результат без оператора и эффект на обращениях с оператором.
5. Для денег используйте фактические счета/потребление модели, инфраструктуру,
   стоимость внедрения и сопровождения. Без этого стоимость пилота неизвестна.

Документы Финуниверситета в демонстрации требуют согласования владельцами процессов.
Поиск по регламентам остаётся лексическим; векторный поиск этим обновлением не добавлен.
