# Подключение 1С

Настройки → Подключение 1С: `/settings/1c`.

Поддерживаются стандартный OData 1С и собственные HTTP-сервисы с JSON. Авторизация: Basic, Bearer или без авторизации. Реквизиты хранятся отдельно для каждой организации. Доступ: администратор с `integrations_manage` и областью всей организации. Пароль/токен не возвращается API и шифруется AES-256-GCM с привязкой к организации. Смена адреса, логина или типа авторизации требует нового секрета.

## Подготовка

1. В 1С опубликуйте стандартный интерфейс OData или собственный HTTP-сервис. Выдайте отдельному пользователю только необходимые права чтения.
2. В `.env` добавьте точный базовый URL в `FLOWOPS_1C_ALLOWED_URLS`, например `https://1c.company.ru/base/odata/standard.odata`. Несколько адресов разделяются запятыми. Адреса разрешает владелец сервера; веб-интерфейс не может расширять этот список. Доверенные адреса локальной сети тоже можно зарегистрировать. HTTP поддерживается для изолированной сети; для передачи реквизитов через внешнюю сеть используйте HTTPS.
3. `FLOWOPS_1C_SECRET_KEY` — 32 случайных байта в Base64. Локальный ключ уже создан в игнорируемом `.env`; в другом окружении создайте собственный. Сохраняйте его вместе с резервной копией конфигурации: потеря ключа требует повторного ввода паролей. Сам ключ в БД не хранится.
4. Перезапустите приложение: `docker compose up -d --build app`. Docker должен видеть адрес 1С: `localhost` внутри контейнера — сам контейнер, для сервиса на Windows обычно нужен `host.docker.internal`.
5. Сохраните настройки в интерфейсе и нажмите «Проверить соединение». OData читает `$metadata` и предлагает опубликованные EntitySet. HTTP вызывает указанный относительный путь проверки и ожидает JSON (например `health`).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/integrations/1c` | Конфигурация без секретов |
| PUT | `/api/v1/integrations/1c` | Сохранение конфигурации и секрета |
| POST | `/api/v1/integrations/1c/check` | Проверка сохранённых реквизитов |
| GET | `/api/v1/integrations/1c/data?resource=Catalog_Сотрудники&skip=0&limit=20` | Чтение страницы данных |

PUT: `mode` (`odata`/`http`), `base_url`, `auth` (`basic`/`bearer`/`none`), `username`, `health_path`, `secret`, `clear_secret`. Пустой `secret` сохраняет текущий секрет только для прежнего адреса и аккаунта. Для удаления секрета выберите авторизацию без реквизитов и отметьте удаление.

OData: `$format=json`, `$top=limit`, `$skip=skip`. HTTP: `limit` и `offset`; свой сервис должен поддерживать эти параметры. Максимум 100 запрошенных записей, 2 МБ ответа, 10 секунд на запрос. Чтение следующей страницы выполняется явно; nextLink от сервера не обходится автоматически. Перенаправления и системные HTTP-прокси отключены, сертификаты HTTPS проверяются. При ошибке ответ 1С не раскрывается в журнале или сообщении API. Во входном `resource` разрешены только относительные сегменты из букв, цифр, дефиса и подчёркивания.

Это подключение выполняет GET-запросы. Автоматического переноса справочников, изменения документов, обмена статусами тикетов и записей в 1С нет: для них сначала требуется согласовать конкретную конфигурацию, поля и права. Входящие обращения из внешнего сервиса можно передавать через существующий `/api/v1/ingest` с отдельным ingest-ключом.

Проверено на изолированных HTTP-стендах и тестовой БД. Реальная база 1С пока не предоставлена.
