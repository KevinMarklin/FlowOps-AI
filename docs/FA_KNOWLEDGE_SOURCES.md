## Дашборд

Статистика `/api/stats` читается из одной read-only транзакции PostgreSQL с Repeatable Read. Обновление в открытом пульте — каждые 5 секунд; при ошибке показана пометка об устаревших данных.

- Deflection Rate = подтверждённые автоответы / все обращения × 100. Числитель: auto_resolved, непустой rag_answer, без operator_reply и без события ответа оператора для текущего обращения. Старые audit-записи до создания заявки не учитываются при повторном использовании ID после демонстрационного сброса.
- Ожидающие подтверждения и ответы оператора не увеличивают экономию.
- Оценка часов = число подтверждённых автоответов × базовое время ручной обработки / 60.
- FLOWOPS_BASELINE_MINUTES: по умолчанию 10 минут, допустимо от значения больше 0 до 480, включая дробные значения. Ошибочная настройка заменяется на 10. Это допущение демо, а не измеренный результат университета; в пилоте заменить замером.
- Нагрузка: открытые new, awaiting_confirmation, assigned_to_operator, resolved, по всем семи техническим отделам, включая Billing и Unassigned. Рядом показано общее число по отделу.

## Показ на защите

1. Выбрать демо-вопрос в окне сотрудника; кнопка только заполняет текст.
2. Отправить обращение; показать ответ, ссылку на имя файла и ограничения памятки.
3. До подтверждения — awaiting_confirmation: Deflection Rate и экономия не растут.
4. Нажать «Помогло, закрыть вопрос»; открыть пульт оператора и увидеть изменение счётчиков из PostgreSQL.
5. Выбрать «Не помогло» у другого обращения; показать нагрузку на соответствующий отдел.

Регламенты работают локально без ключей модели и сохраняются при демонстрационном сбросе. Никакие фиктивные обращения не добавляются в рабочую БД автоматически.
