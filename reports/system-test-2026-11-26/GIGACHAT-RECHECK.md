# Повторное подключение GigaChat

26 ноября 2026. По запросу пользователя активный провайдер переключён с OpenRouter обратно на GigaChat.

## Исправления запуска

- В локальном `.env` настройки GigaChat были закомментированы, включая ключ. Существующий ключ сохранён, настройки активированы и приведены к одному набору без дубликатов.
- `FLOWOPS_AI_PROVIDERS=gigachat`; межпровайдерный fallback выключен.
- `FLOWOPS_AI_ALLOW_SENSITIVE=false`; проверка TLS-сертификатов включена.
- OAuth: `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`; API: `https://gigachat.devices.sberbank.ru/api/v1`; модель: `GigaChat`.
- Приложение пересобрано из текущей рабочей копии и перезапущено. База PostgreSQL не пересоздавалась.

## Проверка результата

До пересборки отдельный процесс успешно получал ответ модели, но API основного приложения возвращал локальный результат; журнал указывал OAuth HTTP 401. После пересборки и запуска тот же проверочный сценарий через API основного приложения прошёл три раза подряд:

| Запрос | HTTP | Режим | Провайдер | Отдел | Время полного сценария |
|---|---|---|---|---|---|
| 1 | 200 | llm | GigaChat | IT | 671 мс |
| 2 | 200 | llm | GigaChat | IT | 516 мс |
| 3 | 200 | llm | GigaChat | IT | 484 мс |

Сценарий: POST `/api/v1/settings/preview` с фиксированным синтетическим текстом о приложении, которое не запускается после обновления; затем GET `/api/stats` и проверка фактически использованного провайдера. Тестовый канал `telegram` задаёт только формат предпросмотра: сообщения не отправляются. Заявки не сохраняются. Данные компании и её регламенты в модель не передавались.

Отдельная проверка генерации JSON также успешна: 436 мс. Воспроизведение через основной API хранится в игнорируемом Git файле `tmp/.debug-tools/service-ai-check.py`; секреты он читает локально и не выводит.

`go test -count=1 ./internal/analyzer ./cmd/server` прошёл. Первоначально локальные HTTPS-соединения тестов блокировались ограничениями среды; повтор с разрешёнными локальными соединениями успешен.

Точная причина расхождения предыдущего процесса и отдельной проверки не установлена; подтверждены неактивные настройки `.env`, OAuth 401 до пересборки и успешный результат после применения конфигурации и пересборки. Защита ответов модели не ослаблялась. Изменений логики продукта для этого подключения не потребовалось. Коммит и push не выполнялись.
