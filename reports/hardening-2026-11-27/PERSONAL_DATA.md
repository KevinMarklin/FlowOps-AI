# Персональные данные и 152-ФЗ: готовность, а не сертификат

Дата оценки: 27 ноября 2026. Входные сведения: сервис компании обрабатывает
персональные и финансовые обращения; схема промышленного размещения неизвестна.
Для хакатона безопаснее использовать только искусственные данные.

## Практические ограничения

1. Регулярные выражения маскирования не обнаруживают все ПДн и не доказывают
   обезличивание. Финансовая информация может одновременно быть коммерческой тайной.
2. Ввод сообщения самим сотрудником в Telegram уже является передачей через этот
   канал. Серверная фильтрация следующего шага не отменяет предшествующую передачу.
3. В локальном Docker используется HTTP на loopback и внутренний PostgreSQL без TLS.
   Промышленная схема должна отдельно защитить транспорт, секреты, диски и копии.
4. В приложении нет доказанной криптографической защиты всей БД/копий и автоматического
   удаления всех копий ПДн. Секреты каналов доступны процессу и администраторам БД.
5. Ранее раскрытые пользователем ключи и пароль приложения почты нужно перевыпустить
   у поставщиков. Удаление из отчёта не отменяет раскрытие; сами значения сюда не включены.
6. Работоспособность/безопасность интеграции и юридическое соответствие — разные
   результаты. Этот прогон не аттестация ИСПДн и не юридическое заключение.
