# FlowOps AI

Платформа внутренней поддержки: обращения с сайта и подключённых каналов, непрерывная переписка, работа специалистов, управляемая база знаний, Яндекс AI Studio, бизнес-процессы и аналитика. Компании изолированы рабочими пространствами; действия проверяются по роли, разрешениям и области доступа.

## Что реализовано

- Создание обращений, уточняющие вопросы, именованные формы и условные поля, вложения и контекст объектов.
- Личная история и очередь специалистов: поиск по ID/фразе, фильтры, состояния прочтения, непрерывный диалог, оценки и закрытие с причиной.
- Telegram/MAX/email, подтверждённые привязки ботов, внешний ingest и ограниченный публичный виджет.
- Роли, 18 разрешений действий, области по владельцу, организации, поддереву подразделений или указанным тикетам.
- Утверждаемые знания: черновики, согласование, версии, публикация, временные и персональные материалы, проверка противоречий Яндексом.
- Настраиваемые классификация, маршрутизация, приоритет, SLA-календари, паузы, эскалации и ограничения ИИ.
- Copilot специалиста: содержание, черновик, вопросы, рекомендации маршрута и процесса с проверкой источников.
- Долговечные workflow: зависимости и параллельные ветви, задачи, согласования, ожидания, разрешённые HTTP-шаги, повторы и отмена.
- Аналитика, личные/общие дашборды, наблюдаемые маршруты, рекомендации улучшений, CSV/XLSX/PDF и расписания отчётов.
- Настраиваемое подключение 1С OData/HTTP: сохранение зашифрованного секрета, проверка соединения и чтение страниц JSON.

## Быстрый запуск: Docker

Нужны Docker и Compose. В корне репозитория:

```powershell
Copy-Item .env.example .env
```

Заполните `.env`, затем:

```bash
docker compose up -d --build
docker compose ps
```

Приложение: **http://localhost:8080**. PostgreSQL текущего Compose: `127.0.0.1:5433`; из контейнера приложения — `db:5432`. Compose задаёт внутренний `DATABASE_URL` для своей БД. Перед использованием вне локальной разработки замените стандартные реквизиты БД и настройте HTTPS.

Первый доступ: зарегистрируйте организацию на экране входа либо активируйте существующее рабочее пространство bootstrap-кодом. Через «Администрирование» создайте персональные приглашения. Приглашения не рассылаются по почте автоматически.

## Запуск Go без Docker

Требования: Go 1.26.11+ и PostgreSQL. Заполните `DATABASE_URL` в `.env` и запускайте из корня проекта:

```bash
go mod download
go run ./cmd/server
```

Сервер загружает `.env`; уже заданные переменные окружения имеют приоритет. Миграции применяются при старте. `schema.sql` — SQL-снимок схемы. При обновлении рабочей установки предварительно сохраняйте резервную копию.

## Яндекс AI Studio

Все production-функции внешней генерации используют Яндекс:

```dotenv
FLOWOPS_AI_PROVIDERS=yandex
YANDEX_API_KEY=your_api_key
YANDEX_FOLDER_ID=your_folder_id
YANDEX_MODEL=aliceai-llm
FLOWOPS_AI_ALLOW_SENSITIVE=false
```

Ключ и каталог вводятся в вашей среде; секреты не коммитятся. Дополнительно настройте режим, разрешённые действия, источники и лимиты организации в «Права и процессы». Наличие ключа само по себе не разрешает передачу любого обращения. Маскирование и политика чувствительных данных действуют до внешнего запроса.

При отключённом провайдере доступны локальные сценарии и ручная поддержка; функции, требующие генерации, возвращают явную недоступность. Copilot не отправляет сообщения и не запускает процессы самостоятельно. Подробнее: [управление ИИ](docs/manual/governance.md), [инструкция Яндекса](docs/YANDEX_ALICE.md).

## Интеграции и публичные адреса

| Переменная | Для чего |
|---|---|
| `FLOWOPS_INGEST_TOKEN` | Отдельный доверенный ввод обращений, отличающийся от кода владельца |
| `FLOWOPS_CALLBACK_URLS` | Точные разрешённые HTTPS callbacks; пусто — выключены |
| `FLOWOPS_PUBLIC_URL` | Доступный сотрудникам адрес для QR |
| `FLOWOPS_1C_ALLOWED_URLS` | Точные базовые URL разрешённых сервисов 1С |
| `FLOWOPS_1C_SECRET_KEY` | 32 случайных байта Base64 для шифрования пароля/токена 1С |
| `FLOWOPS_COOKIE_SECURE` | `true` для установки за HTTPS |

Для внешнего клиента выпускайте отдельный ingest-ключ в интерфейсе. Поле текста входящего сообщения — `message`:

```bash
curl http://localhost:8080/api/v1/ingest \
  -H 'Authorization: Bearer YOUR_INGEST_KEY' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: external-case-2026-001' \
  -d '{"channel":"API","sender":"external-user-17","message":"Не работает рабочий сервис"}'
```

Полный [контракт API](docs/manual/api.md), [повторные доставки](docs/RELIABILITY.md), [настройка 1С](docs/ONEC.md). Получатель workflow HTTP должен поддерживать идемпотентность; произвольное внешнее выполнение «ровно один раз» не обещается.

## Проверки

```bash
go test ./... -count=1 -timeout=240s
go vet ./...
node --test tests/*.test.cjs
```

Для БД-тестов отдельно задайте `FLOWOPS_TEST_DATABASE_URL` на **тестовую** базу `flowops_security_test`. Тесты используют временные схемы. Не запускайте их с URL рабочей базы. Документация имеет проверки каталога, ссылок, прямых маршрутов и безопасного рендеринга.

## Практические ограничения

- Подключение 1С пока читает данные: автоматическая синхронизация справочников и запись документов не реализованы; реальная база ещё не предоставлена.
- Регулярные отчёты доступны на сайте владельцу, без автоматической отправки email.
- Нет SSO, MFA и автоматической проверки владения почтовым ящиком.
- Ограниченные роли не получают общие аналитические или знаниевые контексты, если модуль не умеет ограничить их тем же срезом.
- Сценарный потенциал экономии не является достигнутым финансовым результатом; сравнение до/после не доказывает причинность.
- Университетские и отраслевые стартовые материалы демонстрационные и требуют местного согласования.
- Полная production-приёмка, включая безопасность, нагрузку и проверку всех внешних систем, не считается автоматически завершённой наличием модульных тестов.
