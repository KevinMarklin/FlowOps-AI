# FlowOps AI

FlowOps AI - сервис для обработки обращений сотрудников и клиентов. Он принимает тикеты через HTTP API и omnichannel ingest, определяет отдел и приоритет, ищет ответ в базе знаний и при необходимости передает обращение оператору.

## Возможности

- классификация обращений по отделам и приоритету;
- RAG-ответы на основе Markdown-документов в `knowledge_base/`;
- автоматическое решение тикета после подтверждения пользователя;
- прием обращений из web, email и bot-каналов через единый ingest API;
- обучение базы знаний на ответах операторов;
- простая web-панель в каталоге `web/`.

## Требования

- Go 1.26.11 или новее;
- PostgreSQL;
- API-ключ Yandex AI Studio и идентификатор каталога для всех функций ИИ.

## Защита сервисного контура

Вход по рабочей почте и паролю, активация и восстановление описаны в [инструкции по входу](docs/AUTHENTICATION.md).

Персональные роли, управление командой и изоляция компаний описаны в [инструкции по доступам](docs/ACCESS_CONTROL.md). Аналитика доступна аналитикам и администраторам; настройки каналов и доступов — администраторам. Сотрудник видит только свои обращения.

По умолчанию обработка локальная: наличие API-ключа само по себе не разрешает передачу заявок модели. См. [настройку и изменения безопасности](SERVICE_HARDENING.md). HTTP ingest требует отдельного `FLOWOPS_INGEST_TOKEN`; callbacks выключены без явного списка `FLOWOPS_CALLBACK_URLS`.

## Быстрый старт

1. Создайте базу PostgreSQL и скопируйте `.env.example` в `.env`.
2. Заполните `DATABASE_URL` и, при необходимости, `GEMINI_API_KEY` или `AI_API_KEY`.
3. Установите зависимости:

   ```bash
   go mod download
   ```

4. Запустите сервер:

   ```bash
   go run ./cmd/server
   ```

По умолчанию API доступен на `http://localhost:8080`. Таблица `tickets` создается автоматически при запуске; SQL для ручной инициализации находится в `schema.sql`.

## API

Повторная отправка без дубликатов: [контракт ключей и поведение каналов](docs/RELIABILITY.md). Примеры ниже показывают тело запроса; защищённые операции также требуют действующей авторизации и CSRF для сеанса сайта.

Создать тикет:

```bash
curl -X POST http://localhost:8080/api/tickets \
  -H "Content-Type: application/json" \
  -d '{"user_email":"user@example.com","raw_text":"Не работает VPN"}'
```

Получить список тикетов:

```bash
curl http://localhost:8080/api/tickets
```

Принять обращение из канала:

```bash
curl -X POST http://localhost:8080/api/v1/ingest \
  -H "Content-Type: application/json" \
  -d '{"channel":"web","sender":"user@example.com","message":"Не работает VPN"}'
```

Дополнительные endpoints для статистики, обратной связи и управления базой знаний зарегистрированы в `cmd/server/main.go`.

## Тестирование

Запустить модульные тесты:

```bash
go test ./...
```

Для API-проверок после запуска сервера доступны PowerShell-скрипты `test_api.ps1` и `test_all.ps1`.

## Конфигурация

Основные переменные окружения описаны в `.env.example`:

- `PORT` - порт HTTP-сервера;
- `DATABASE_URL` - строка подключения к PostgreSQL;
- `AI_BASE_URL` - OpenAI-compatible endpoint AI-провайдера;
- `AI_API_KEY` / `GEMINI_API_KEY` - секретный API-ключ;
- `AI_MODEL` - используемая модель.

## Демо для Финансового университета

В окне сотрудника доступны шесть кнопок: справки об обучении и для военкомата, FA-WiFi, восстановление доступа, командировка и авансовый отчёт. Кнопки заполняют вопрос; отправка выполняется отдельно. Инструкции `knowledge_base/fa_*.md` работают и в локальном режиме. Они демонстрационные; подтверждённые источники и ограничения собраны в [описании пакета](docs/FA_KNOWLEDGE_SOURCES.md).

В разделе «Аналитика» для аналитиков и администраторов — живая статистика PostgreSQL с обновлением каждые 5 секунд: число обращений, Deflection Rate, открытая нагрузка по отделам и оценка сэкономленных часов. Подтверждённый автоответ учитывается после положительной обратной связи, при отсутствии ответа оператора. Оценка часов использует `FLOWOPS_BASELINE_MINUTES` (по умолчанию 10 минут на обращение); это явное допущение, которое нужно заменить замером на пилоте.
